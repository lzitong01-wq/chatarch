# 《对话考古 · ChatArch》项目规划书

> WorkBuddy「1024 造物挑战」参赛作品 · v1.1 · 2026-10-25

**当前进度**：S1—S5 已完成 ✅；整合优化与最终检测已完成 ✅；S6 投稿材料齐备 ✅、应用已发布 ✅；两轮界面优化已完成并同步线上 ✅（33 项 E2E 全通过、0 console 错误）；剩余：平台投稿提交 + 社媒发布（需用户本人账号操作）。

## 一、最终目标

交付一个**公开可访问的纯前端网页应用**：用户粘贴一段与 AI 的协作对话记录，工具自动将其解析、分析，并以「考古」为主题呈现为四视图（共创编年史 / 废稿博物馆 / 协作画像 / 卡点热区），可一键导出考古报告。作品用于投稿大赛，并配套社媒分享内容。

## 二、作品级验收标准（终态 checklist）

| # | 验收项 | 标准 |
|---|---|---|
| 1 | 核心闭环 | 粘贴对话 → 自动解析 → 四视图呈现 → 报告导出，每环真实可用，无占位按钮、无死链接 |
| 2 | 开箱即用 | 示例数据一键加载，评委 3 分钟内看到完整效果 |
| 3 | 解析质量 | 对 ≥30 轮真实对话：分轮正确、阶段划分合理、事件标记有文本依据 |
| 4 | 视觉完成度 | 考古主题视觉系统统一（土层色系 + 博物馆图录质感），无默认样式、无破损布局、无卡通元素 |
| 5 | 稳定性 | 无 console 报错；1280×720 与 390×844（移动端）分辨率下布局正常 |
| 6 | 投稿就绪 | 体验链接公开可访问、1—3 张截图、作品说明、社媒文章带话题 #WorkBuddy #1024程序员节 |

## 四、阶段规划（8 天窗口，截稿 11/1 23:59）

日历：D1=10/25（六）… D7=10/31（五），D8=11/1（日）投稿日，含 1 天缓冲。

### S1 项目骨架与解析引擎（D1 · 10/25）
- **内容**：项目骨架（index.html + 设计变量 + JS 模块结构）；对话解析器 parser.js，支持多格式（"用户/助手"、"Human/Assistant"、"### User/### Assistant"、无标记兜底），输出统一 messages 数据模型；数据模型定义文档。
- **验收**：3 种格式测试输入均输出正确轮次结构；入口页可打开；解析器有自动化测试（Node 脚本）且通过。

### S2 分析引擎（D2 · 10/26）
- **内容**：特征提取（方向变更/犹豫/突破/异常长度信号）；阶段划分（探索期/攻坚期/收尾期）；废稿检测；卡点聚类；人机贡献统计。
- **验收**：对 ≥30 轮长对话输出合理分析结果 JSON；每个事件标记可溯源到触发文本。

### S3 四视图界面（D3—D4 · 10/27—28）
- **内容**：导入页（粘贴 + 示例数据一键加载）；时间线视图（地层压缩带 + 节点交互）；废稿博物馆卡片墙；协作画像堆叠面积图；卡点热区。
- **验收**：四视图均渲染真实分析数据；交互可用；无占位组件。

### S4 报告生成与导出（D5 · 10/29）
- **内容**：考古报告（项目概要/阶段/关键决策链/废稿清单/协作画像）；导出为图片与文本。
- **验收**：一键生成完整报告；导出文件内容完整可用。

### S5 视觉系统与示例数据（D6 · 10/30）
- **内容**：考古主题视觉全量打磨；示例数据精修（基于论文创作过程脱敏构造的 ≥30 轮长对话）。
- **验收**：视觉统一无残留；示例数据一键加载后四视图效果完整惊艳。

### S6 测试、投稿与社媒（D7—D8 · 10/31—11/1）
- **内容**：全链路测试与 bug 修复；投稿材料（截图 + 作品说明）；社媒文章发布；提交投稿。
- **验收**：终态 checklist 全部打勾；投稿完成并留证。

## 五、多 Agent 协作方式

- **统筹者（我）**：架构设计、核心代码、阶段验收、向你汇报。
- **子 Agent 派发原则**：仅派发边界清晰、可独立验证的任务（如测试数据构造、视觉探索、文案撰写），核心实现由统筹者完成以保证代码一致性。
- **汇报节奏**：每完成一个阶段汇报一次；遇阻塞即时上报。

## 六、风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| 解析启发式不准 | 事件标记误报 | 定位为"启发式分析"并在 UI 明示；提供手动校准功能 |
| 示例数据效果平淡 | 评委 3 分钟看不懂 | D6 专项打磨；示例对话要戏剧性（有方向变更、有废稿、有卡点） |
| 前端工作量超预估 | S3/S4 延期 | 核心闭环不动，装饰性功能（动画、皮肤）最先砍 |
| 移动端适配遗漏 | 体验分受损 | S6 专项检查 390×844 布局 |

## 七、技术约束

- 纯前端单页应用，无后端依赖；数据仅存内存/localStorage。
- 图表用手绘 SVG/Canvas，不引重依赖。
- 交付形态：静态文件目录，可直接托管访问。
